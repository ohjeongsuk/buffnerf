# BuffNerf PRD

> 원본: https://claude.ai/artifact/7WCh2biP4gU8fwjQb2vSQD (2026-11-06 기준 rev 14)

BuffLog(버프로그)는 리그 오브 레전드, 오버워치, 이터널 리턴의 패치노트를 AI로 요약하고, 캐릭터별 상향(버프)·하향(너프) 변화를 타임라인으로 보여주는 풀스택 웹 서비스입니다. 개발 기간 2주 안에 MVP를 배포하는 것이 목표입니다.

## 개요

패치노트를 읽지 않고도 "이번 패치에서 무엇이, 왜, 얼마나 바뀌었는지"를 1분 안에 파악하게 하는 것이 목표입니다.

**문제**

- 패치노트는 길고 전문 용어가 많아 핵심을 찾기 어렵습니다.
- 특정 캐릭터가 여러 패치에 걸쳐 어떻게 바뀌었는지 한눈에 볼 수 없습니다.
- 해외 게임은 영문 패치노트만 제공되는 경우가 많습니다.

**목표**

1. 패치노트를 AI로 3줄 요약하고, 영문 패치노트는 한국어로 제공한다.
2. 밸런스 변경을 구조화된 데이터(캐릭터, 항목, 상향/하향, 변경 전후 수치)로 추출해 타임라인과 차트로 보여준다.
3. 롤은 공식 버전 데이터와 AI 추출 결과를 대조해 AI 정확도를 수치로 공개한다.

**성공 기준**

| 지표 | 목표 |
| --- | --- |
| 수집된 패치 수 | 롤 최근 20개 버전 이상, Steam 게임 2개 각 10개 이상 |
| 롤 기본 스탯 AI 추출 재현율 (실제 변경 중 AI가 맞게 찾은 비율) | 85% 이상 |
| 롤 기본 스탯 AI 추출 정밀도 (AI가 뽑은 변경 중 맞은 비율) | 85% 이상 |
| 패치 상세 페이지 응답 시간 | 캐시 적중 시 1초 이내 |
| 배포 | 외부에서 접속 가능한 URL 1개 |

## 사용자와 시나리오

주 사용자는 패치 내용을 빠르게 확인하고 싶은 게이머이며, 포트폴리오를 검토하는 채용 담당자도 2차 사용자로 봅니다.

| 사용자 | 상황 | 원하는 것 |
| --- | --- | --- |
| 롤 플레이어 | 새 패치 직후, 주 챔피언이 바뀌었는지 궁금함 | 내 챔피언의 변경 내역과 과거 이력 |
| Steam 게임 플레이어 | 영문 패치노트가 길어 읽기 부담됨 | 한국어 3줄 요약 |
| 채용 담당자 | 포트폴리오 링크를 열어 봄 | 데모 데이터로 핵심 기능을 1분 안에 체험 |

**대표 시나리오**

1. 사용자가 게임을 선택하고 최신 패치를 엽니다.
2. 상단에서 AI 3줄 요약을 읽고, 아래 표에서 상향/하향 캐릭터를 확인합니다.
3. 관심 캐릭터를 눌러 지난 패치들의 변경 이력을 타임라인으로 봅니다.
4. 변경 항목마다 원문 근거 문장을 펼쳐 AI 추출이 맞는지 확인합니다.

## 기능 요구사항

P0는 2주 안에 반드시 완성하고, P1은 시간이 남을 때, P2는 이후 확장으로 둡니다.

| ID | 기능 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| F1 | 패치 수집 | 롤 Data Dragon 버전·챔피언 JSON, Steam 뉴스 API를 스케줄러로 주기 수집 | P0 |
| F1-b | 롤 패치노트 원문 수집 | 공식 패치노트 페이지를 자동 수집(크롤링)한다. 자동 수집에 실패하면 관리자 등록 API로 원문을 직접 붙여넣어 저장한다 | P0 |
| F2 | 롤 스탯 diff | 연속 두 버전의 챔피언 기본 스탯을 코드로 비교해 변경 항목 저장 | P0 |
| F3 | AI 요약 | 패치별 3줄 요약, 영문은 한국어로 번역 요약 | P0 |
| F4 | AI 구조화 추출 | JSON 스키마로 캐릭터·항목·유형·변경 전후 값·근거 문장 추출 | P0 |
| F5 | 패치 목록·상세 화면 | 게임 선택, 패치 목록, 요약과 변경 표 | P0 |
| F6 | 캐릭터 타임라인 | 캐릭터별 변경 이력을 시간순으로 표시 | P0 |
| F12 | 수동 수집 실행 | 관리자 API로 게임별 수집과 AI 처리를 즉시 실행한다. 배포 직후 데모 데이터를 채우는 용도 | P0 |
| F7 | 패치 통계 차트 | 패치별 상향·하향 캐릭터 수 차트 | P1 |
| F8 | AI 정확도 계산 | 롤 패치마다 AI 추출과 F2 diff의 재현율·정밀도를 패치 상세 API로 제공 (화면 표시는 뺌) | P1 |
| F9 | ~~패치노트 분류~~ (범위 외, 2026-11-09) | 공식 패치노트 페이지만 수집하므로 이벤트·세일 공지가 섞이지 않아 불필요 | — |
| F10 | 롤 스킬 수치 diff | 스킬 계수 비교 (데이터 누락 시 보완 소스 필요) | P2 |
| F11 | 게임 추가 | Steam 게임을 설정만으로 추가 | P2 |

**F1-b 동작 방식**

1. 새 롤 버전이 수집되면 크롤러가 해당 버전의 공식 패치노트 페이지를 읽어 본문을 저장한다.
2. 페이지를 찾지 못하거나 본문 파싱에 실패하면 Patch를 '원문 대기(PENDING_CONTENT)' 상태로 두고 실패 이유를 기록한다.
3. 관리자가 등록 API로 원문을 붙여넣으면 상태가 '원문 확보(READY)'로 바뀌고, 이후 AI 요약·추출이 자동으로 이어진다.
4. 원문이 어디서 왔는지(CRAWLED / MANUAL)를 저장해, 자동 수집 성공률을 README에서 설명할 수 있게 한다.

크롤링 전에 대상 사이트의 이용약관과 robots.txt를 확인하고, 요청 간격을 두어 서버에 부담을 주지 않는다.

## 데이터 모델

게임마다 수집 방식은 달라도 저장 구조는 4개 엔티티로 공통화합니다.

| 엔티티 | 주요 필드 | 비고 |
| --- | --- | --- |
| Game | id, name, source(LOL / STEAM), externalId(Steam appid) | 수집기 선택 기준 |
| Patch | id, gameId, version, title, publishedAt, rawContent, contentSource(CRAWLED / MANUAL), contentStatus(READY / PENDING_CONTENT), contentError, summaryKo, isPatchNote | rawContent는 정리된 원문, 원문이 없으면 PENDING_CONTENT |
| BalanceChange | id, patchId, characterName, attribute, changeType(BUFF / NERF / ADJUST), before, after, evidence, source(AI / DIFF) | 같은 항목을 AI와 DIFF로 각각 저장해 대조 |
| AiRun | id, patchId, task(SUMMARY / EXTRACT / CLASSIFY), model, promptVersion, tokens, status, createdAt | 재호출 방지와 비용 추적 |

- Patch는 (gameId, version)에 유니크 제약을 걸어 중복 수집을 막습니다.
- **정확도 비교 기준**: 같은 patchId에서 챔피언, 스탯 항목, 변경 후 수치가 모두 같으면 '맞음'으로 봅니다. 비교 대상은 Data Dragon에 있는 기본 스탯만이며, 스킬·아이템 변경은 제외합니다.
- **이름 정규화**: AI 추출 결과의 챔피언 이름과 스탯 이름(예: 아트록스 / 공격력)을 Data Dragon의 영문 ID와 키(Aatrox / attackdamage)로 바꿔 저장해야 비교할 수 있습니다. 챔피언은 Data Dragon의 한국어 이름 데이터로, 스탯은 매핑 표로 변환합니다.
- **재현율** = 맞음 개수 ÷ DIFF 변경 개수, **정밀도** = 맞음 개수 ÷ AI 추출 개수. 두 값은 패치 상세 API 응답(`accuracy`)에 담습니다.

## 비기능 요구사항과 범위 외

**비기능 요구사항**

- **비용**: 같은 패치에 같은 프롬프트 버전으로 LLM을 두 번 호출하지 않는다(AiRun으로 확인).
- **안정성**: 외부 API 실패 시 재시도 후 실패 기록만 남기고 다음 수집을 계속한다.
- **보안**: LLM·Steam API 키는 서버 환경변수로만 관리하고 프론트에 노출하지 않는다.
- **신뢰성**: 모든 AI 추출 항목에 원문 근거 문장을 함께 저장하고, 스키마 검증에 실패한 응답은 저장하지 않는다.
- **반응형**: 모바일 너비에서도 패치 상세와 타임라인을 볼 수 있다.

**범위 외 (이번 2주에 하지 않음)**

- 회원가입·로그인, 즐겨찾기, 알림
- 롤·Steam 외 게임 소스
- 이미지·표로만 된 패치 내용 해석
- 커뮤니티 기능(댓글, 투표)
- F9 패치노트 분류: 공식 패치노트 페이지(롤·오버워치·이터널 리턴)만 수집하므로 필요 없음 (2026-11-09)

## 2주 일정

백엔드 데이터 파이프라인을 1주차에 끝내고, 2주차는 화면과 배포에 씁니다.

| 기간 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1~2일 | 공통 도메인·ERD, PatchCollector 인터페이스, 프로젝트 세팅, AWS 예산 알림. **AI 사전 시험**: 롤 패치 1개 원문으로 Sonnet 요약·추출을 미리 돌려 보고 결과를 diff와 손으로 비교 | 엔티티 마이그레이션 완료, 추출 JSON 형식 확정 |
| 3~5일 | 롤 수집기, 버전 간 기본 스탯 diff, 패치노트 원문 크롤러와 수동 등록 API (F1, F1-b, F2) | 최근 20개 버전 diff와 원문 저장 |
| 6~7일 | 오버워치·이터널 리턴 수집기, 본문 정리 (F1) | 게임 2개 패치노트 저장 |
| 8~9일 | LLM 연동: 1~2일차에 확정한 프롬프트로 요약·추출 자동화 (F3, F4) | 스키마 검증 통과 결과 저장 |
| 10~12일 | Next.js 화면 5개, 관리자 수동 수집 (F5~F8, F12) | 대표 시나리오 4단계 동작 |
| 13~14일 | AWS 배포, 수동 수집으로 데모 데이터 채우기, README | 외부 URL 접속 가능, 데이터가 채워진 상태 |

일정이 밀리면 Steam 게임을 1개로 줄이고 F7·F8을 뒤로 미룹니다.
